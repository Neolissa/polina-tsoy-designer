TVIP

Turning one legacy interface into a system for different devices and viewing contexts.

Role
Product Designer
Scope
Research, UX/UI, profiles, component library
Scale
5 platforms · 4 usage contexts
Constraint
Existing backend and a working legacy interface

Context

One interface served fundamentally different viewing modes

The product already had a working MVP, backend, and API, but its interface no longer reflected its capabilities. Family viewing on TV, individual viewing in transit, and archive exploration on desktop required different priorities.

Key insight: one screen could not simply stretch across five devices. The data model and rules could stay shared; hierarchy and controls had to reflect context.

Scope boundary: the interface evolved on top of the existing backend rather than rebuilding it.

Three decisions

From viewing contexts to one product system

01 · Usage contexts

Group requirements by viewing situation

Research and a feature-request board revealed four recurring contexts. They informed priorities for both profiles and platforms.

Family viewing

TV, simple navigation, shared content, and parental controls.

Individual

Mobile, personal recommendations, and saved progress.

Background

Tablet playback without continuous attention.

Archive exploration

Desktop, advanced search, collections, and detailed navigation.

02 · Profile system

Make each profile a distinct viewing space

History, recommendations, settings, and parental controls were attached to a profile. Fast switching preserved a shared account without mixing viewer needs.

  • History: continue viewing on another device.
  • Settings: preferences and restrictions inside a profile.
  • Control: separate rules for children’s profiles.

03 · Multiple platforms

Keep the rules shared while adapting hierarchy and controls

The component library supported TV, desktop, mobile, and tablet without forcing identical behavior. Screen distance, size, and input method shaped each composition.

Trade-off: maximum reuse would have simplified implementation but weakened TV and mobile experiences. The profile model, states, and visual rules stayed shared.

Delivered scope

Reflection

What defined the quality of the solution

The core work was not producing five visual versions. It was separating what remained shared—data, states, and actions—from what depended on the device and viewing situation.

Day and night themes show two expressions of the same system and make the visual directions easier to compare.
