Problem and evidence

Interface debt was already affecting delivery

The product had accumulated more than 200 styles and repeated patterns. Familiar elements were rebuilt from scratch, while White Label support required manual interface rework.

What I checked: an interface audit exposed competing rules; developer interviews confirmed repeated layout decisions and style conflicts.

Key insight: a full redesign would have interrupted product work. The system needed to ship incrementally and become useful inside current feature delivery.

Three decisions

A system the team could adopt incrementally

01 · Migration

Evolutionary refactoring instead of a large redesign

I updated components as product work created a real need. New screens used shared rules immediately, while existing surfaces moved onto the system without a separate roadmap freeze.

Trade-off: old and new rules coexisted for a period, but the team continued shipping product changes.

02 · Architecture

From 200+ styles to tokens and 35 components

Components received shared states and semantic tokens. Visual language, interaction logic, and implementation no longer diverged across product areas.

Tokens
Separate the purpose of a color or spacing value from a specific brand.
Components
Reuse states and rules instead of local layout decisions.
Coverage
The builder covered ≈80% of the interface; complex workflows remained custom.

System rules

  • Semantic roles firstA component consumes a role token rather than a local hex value.
  • One state modelShared component states are defined once and reused across the product.
  • Exceptions stay explicitUnique assessment workflows are not forced into a generic pattern.

03 · White Label

Change the brand through tokens, not copied screens

A theme changes accents, surfaces, and states inside one component structure. The interactive proof below shows that a brand change does not alter information architecture or behavior.

Reflection

What I would introduce earlier

Variables: I would introduce them earlier to separate semantic tokens from brand values from day one.

Documentation: I would add dedicated guidance for content managers, not only designers and developers.
